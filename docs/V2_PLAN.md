# V2 改进方案（产线反馈）

来源：2026-10-21 产线反馈 5 点（UI 体验、工位配置、报告、按键测试失败、陀螺仪缺失）。
按优先级拆三个批次：V2.1 修复+体验（当天可完成）、V2.2 配置与工位（核心新功能）、V2.3 报告与陀螺仪。

## 1. 按键测试失败 —— 原因分析（先修，属 bug）

**原版行为**（`OnBnClickedButton1Key`）：执行 `camera-factory 15`，在输出里找字符
`5`（开机键）/`6`（音量键）/`4`（多功能键）；找到哪个就打印哪个键 PASS，
**一个都没找到时什么都不打印**——原版把"无人按键"静默吞掉了。

**我们的移植**：`keys.is_empty() → Verdict::Fail`（比原版严格，见 runner.rs）。
一键全测时没人守着按键，固件的监听窗口内无按键输出 → 必然 FAIL。

**结论**：按键是**半自动测试**（需要操作员在监听窗口内按键），不该当纯自动项跑。

### 修复方案（V2.1）

1. 改为**引导式流程**（类似指示灯/MIC）：
   - 弹非阻塞提示窗"请依次按下：开机 / 音量 / 多功能 键"，实时回显已检测到的键；
   - worker 侧带超时轮询（`listen_secs`，默认 10s，可配）；
   - 收齐"必测键集合"（默认 4/5/6 三个，工位可裁剪）→ 自动 PASS；
   - 超时未收齐 → 显示缺哪些键，操作员可选"强制通过/不通过"（与产线确认默认值）。
2. 解析加严（可选开关，默认兼容原版 `contains`）：
   strict 模式只认**独立数字行**（`^\s*[456]\s*$`），避免版本号"1.0.**5**"、
   电压"**4**.2V"这类假阳性——原版同样有此隐患，只是被静默行为掩盖。
3. 原版细节差异记录：MFC `Find("5") > 0` 要求匹配位置 > 0，我们的 `contains` 含位置 0，
   对真实输出（有多行前缀）无行为差异，不单独处理。

## 2. UI 优化（V2.1）

- **字号**：默认 `pixels_per_point ≥ 1.25`（取系统值与 1.25 的较大者），
  保留 egui Ctrl+滚轮缩放；正文字号 14→16，面板标签 18。
- **进度显示**：顶栏 `ProgressBar`（已完成/总数）+ 当前项名 + 已耗时；
  worker 已有 `Current/Result` 事件，UI 侧补计数即可。
- **实时日志**：底部日志面板（等宽小字、时间戳、自动滚动、保留 200 条）。
  重新引入 `UiEvent::Log`（M5 清死代码时删过 `Note`，当时确实无发送方；
  现在 worker 每步发：发送的 adb 命令、输出首行摘要、判定原因、耗时）。
- 状态栏保留最后一行日志，与日志面板同源。

## 3. 测试项配置页 + 工位档案（V2.2，核心）

两个工位需求：**模组工位**（无整机，浅测：如 WiFi 只验驱动）、**整机工位**（深测：
如 WiFi 还要速率）。

### 配置模型（`config.toml`，serde 双向）

```toml
# 顶栏下拉选择当前工位
station = "module"                     # module | complete

[profile.module]                       # 模组工位：浅测
items = ["info", "btmac", "wifi", "sdcard", "photo", "led"]

[profile.complete]                     # 整机工位：全项深测
items = ["info", "btmac", "wifi", "sdcard", "charger", "battery",
         "keys", "photo", "video", "led", "mic", "gyro"]

[item.wifi]
depth = "driver"                       # driver | throughput；complete 工位配 throughput

[item.wifi.throughput]                 # depth = throughput 时生效
method = "ping"                        # ping（默认，普适） | iperf3（设备端需预装）
ping_count = 20
loss_max_pct = 0.0
rtt_max_ms = 100

[item.keys]
listen_secs = 10
required = [4, 5, 6]                   # 模组工位可裁剪

[item.gyro]
# 固件暂无 camera-factory 命令：先用通用 shell 采样，固件加上后改 cmd 即可
cmd = "dumpsys sensorservice | grep -A2 Gyroscope"
# 通过判定：两次采样数值有变化（芯片活着且在输出数据）
```

- 配置文件优先级：exe 同目录 `config.toml` > 内置默认；设置页可视化编辑（勾选测试项、
  每项展开深度参数），保存即写回。
- **自定义测试项框架**：`[custom.<name>]` = 任意 `cmd` + `pass_regex` + `fail_regex` +
  是否人工确认。陀螺仪先用内置定义走此框架，固件支持后无需改代码换命令。

### WiFi 速率实现（depth = throughput）

- `ping` 法（默认）：`adb shell ip route` 取网关 → `adb shell ping -c N 网关`，
  解析丢包率与 avg RTT，超阈值 FAIL；detail 记录原始统计行。
- `iperf3` 法（可选）：`adb forward tcp:5201` + 设备端 `iperf3 -s`，宿主机打流测 Mbps，
  阈值 `min_mbps` 可配。设备端未预装 iperf3 的产线用 ping 法即可。
- 深度为 driver 时保持现状（`camera-factory 5` 不含 FAIL 即过）。

## 5. 陀螺仪测试（V2.3）

原工程无陀螺仪命令（全源码检索无 sensor 相关 camera-factory 调用），**需要固件配合**。
落地路径：

1. 短期（不依赖固件）：用自定义项框架 + `dumpsys sensorservice` 采样两次，
   数值变化即 PASS（验证陀螺仪芯片上电、注册、出数）；
2. 建议 firmware 侧新增 `camera-factory 16`（返回陀螺仪自检结果），
  上线后改配置 `cmd` 即可，程序不用重发版。

### V3.3.1 修复：测试项行消失（真机反馈"功能测试显示项目没有了"）

V3.2 重写行组件时用了 `ui.horizontal_centered` + `with_layout(right_to_left(
Align::Center))`。egui 水平布局 + 垂直 Center 对齐时，**每个子 widget 的
frame 会撑满剩余可用高度**（`Layout::next_frame_ignore_wrap`：`is_horizontal()
&& vertical_align()==Center` → `frame_size.y = max(available_rect.height())`）。
侧面板高度无界（一直延伸到面板底），第一行就把整栏剩余高度吃掉（450px），
后 11 行全被顶出裁剪区——界面只剩一行。V3.1 用普通 `ui.horizontal`
（Align::Min，不填充）所以没这问题；此前没发现是因为当时的截图核对被桌面上
其他窗口污染。修复：行内一律 `Align::Min`（单行布局视觉无差），`theme::dot`
按正文行高分配高度、圆画中心保持光学居中。**判别法**：TopBottomPanel/Window
有 sizing pass（Center 自动降级 Min）不受影响；SidePanel 内容、ScrollArea
内容无界，禁用 Center 对齐的水平行。

## V3.4.1 修复：统计卡两列挤在左侧（真机反馈"右侧统计布局乱"）

现象：2×2 网格实际渲染成"内容全部挤在卡左 ~120px、右侧 2/3 留白"。
根因：egui `Grid` 的列宽 = 该列最宽单元格**内容宽度**（shrink-to-content），
`ui.vertical` 单元格不撑宽，两列合计仅 ~90px 且各自左对齐、列宽不等。
修复：弃 Grid 改**等宽瓦片**——预取半宽 `w = (avail - 10) / 2`，每块 CARD
圆角瓦片 `set_width(w - 20)`（min+max 同钉，Center 居中才有界可依），值大号
语义色居中 + 灰小标签居中；横向余量 2px 防 `horizontal` 溢出换行。

同批布局配平：测试项行内边距 (8,4)、滚动区内行距 4（pitch 40→32px，
12 项在 1280 宽一屏放下，ScrollArea 保留作矮屏兜底）；左栏 236→240、
右栏 320→300（媒体井加宽）；日志面板默认高 150→140。

排查教训：反馈截图（6.png）实为**重建前旧进程**所截（单列旧布局）——
改完 UI 收到"还是老样子"反馈时，先确认对方运行的是不是重建后的二进制，
再怀疑代码；像素核对用扫描线/低阈值细采，粗步长采样会漏行误判"空白"。

## V3.6.2（真机日志：按键粘包，2026-10-23）

真机 camera-factory 15 输出存在**串口粘包**：垃圾串 HC0 糊在报文前后
（`Key 4HC0`、`HC0…\Key test enable`）。词级匹配（key 与数字须为独立
空白分词）在 `Key 4HC0` 上永远失配——多功能键收不齐、弹窗转人工改判。
改为模糊匹配：`key`（大小写不敏感）后跳过空白、紧跟目标数字即命中，
数字后跟任意字符（粘连垃圾/粘连数字）都算；`keyboard 4`、
`Key test enable/disable`（key 后是字母）仍不误判。真机粘贴样例入单测。

## V3.6.3（真机日志：按键收齐不前进，2026-10-23）

真机 V3.6.2 后复测：弹窗三键已全部点亮，流程却停在按键项不往下走
（run1 等了 27s 手动停止，run2 直到日志结束）。根因与 V3.6.1 麦克风
同类——**固件 v2.4.2 的 `camera-factory 15` 收齐按键后并不退出**
（T33 旧固件打 `1` 自退回提示符），而 keys_flow 把判定押在命令返回上：
流式回调只点亮弹窗，`Pass` 分支永远等不到执行，直到 60s 单项超时。

修复（同 mic 回环的"发射即判"模式）：

- keys_flow 重构为 `spawn_shell` + 读线程：读线程按字节读行解码累积、
  增量解析发 `Update`（实时点亮保留 V3.1 行为），**发现必测键收齐立即
  发 `Collected`，不等 EOF**；主流程 250ms 切片等信号（结构同
  recv_manual，响应停止/单项超时），收到 `Collected` 即杀本地 adb 会话
  判 PASS。
- 命令自行退出（`Done`，旧固件自退行为）或单项超时（`Timeout`）才走
  原有"未收齐"人工弹窗：重测/强制改判/超时判负路径不变。
- 读线程绝不持有 UI Sender 克隆：杀 adb 后孤儿孙进程可能仍握管道写端，
  读线程会吊到它退出，持有 Sender 会让 UI 事件通道迟迟不关——增量
  点亮改经信号通道由主循环转发。
- 新增回归测试：假 adb 输出三键后 `sleep 30` 不退出，断言收齐即判
  PASS 且 <15s（模拟真机 v2.4.2 行为）。
- 顺带修复既有测试竞态：runner 假 adb 测试未拿 TEST_LOCK，与 worker
  序列测试并行时互抢进程级 `ADB` 环境变量（媒体场景偶发 FAIL）；
  `adb::shell_stream`/`exec::stream_lines` 失去唯一调用方，删除。

附带发现（未改代码）：该真机 camera-factory 10 蓝牙 MAC 首轮输出为空
判 FAIL、复测正常，疑似设备侧偶发；陀螺仪 `gyroscope-test:false`
（WhoAmI=0x0）为该机硬件/固件真实不良。

## V3.8（USB 设备在位监测，2026-10-23）

需求澄清（耳机产品）：被测耳机经 **USB 连电脑（adb）**，所有测试项依赖
这个连接——插入要检测到（才能开测），拔出也要检测到（要中止）。
非 3.5mm 耳机口检测。

实现：

- **devwatch 模块**：后台线程每 1.5s 跑 `adb devices`（只认 `device`
  状态；offline/unauthorized 不算在线），状态机
  未连接/在线(序列号)/多台；查询失败保持上一状态不当作拔出（防抖，
  adb 未装/server 抖动不误触发）。状态沿变化经通道通知 UI 并重绘。
  产线固件序列号恒为 123456，插入检测靠"状态沿"而非序列号比对，
  同号换机也能触发。
- **开测门槛**：未连接/多台时"开始测试"禁用（按钮下有提示文字，
  顶栏有指示），start_run 内同款兜底；顶栏右侧常驻指示
  灰●未连接 / 绿●设备 123456 / 琥珀●多台设备。
- **测试中拔出 → 立即中止**：复用停止路径，exec 停止请求增加原因
  （手动 / 设备拔出），当前项与剩余项记跳过"设备已拔出"、报告照常
  落盘；命令强杀消息同样按原因。
- **关键坑**：停止测试置位的全局 ABORT 在"停止一轮后"到"下轮开始前"
  一直残留，监测查询若走普通执行入口会被当作停止请求误杀——监测
  从此冻结、插拔失灵。监测专用 `output_no_abort`（超时兜底仍生效），
  有回归测试锁住。
- **插入自动开始**（可选，默认关）：设置页"连接"小节勾选后，检测到
  设备上线沿且空闲即自动开始全测（插上即测，拔出换下一台）。

测试 41 个（新增：exec 原因消息/免误杀、devwatch 分类与状态机、
config auto_start、worker 拔出中止场景并入序列大测试）。
